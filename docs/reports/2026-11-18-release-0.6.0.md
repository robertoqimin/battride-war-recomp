# Report of November 18, 2026: version 0.6.0, Linux and Windows

## Summary

- **Two packages:** 0.6.0 is the first release with a Windows package (a zip
  with the launcher and its own MSYS2 compilers) beside the Linux AppImage.
  Both import the player's ISO, translate their EBOOT and compile the game on
  their computer, with GCC optimization profiles trained for each compiler.
- **Faster fights:** in the STG02 benchmark the game each package builds is
  faster than 0.5.2 on both GPUs of the test laptop: on Linux 58.5 against
  54.8 fps on the integrated Radeon and 59.7 against 57.0 on the GTX 1650. On
  Windows, which had no 0.5.2 package, against the first Windows package of
  November 12: 55.0 against 46.3 and 57.7 against 56.3. The worst 5 seconds
  improved more than the average (section 2).
- **Fewer waits on loads:** the game keeps its compiled graphics pipelines on
  disk; on the GTX 1650 the 198 pipelines up to the first fight took 13 ms
  instead of 113 ms (1.5 s with the driver's cache empty).
- **Lost and rebuilt:** the working copy with the November 15-16 packages and
  profiles was lost on November 17. Both packages were rebuilt from the same
  code (`359ab9c`, plus docs) with newly trained profiles and tested again
  (section 4).

Test machine for everything below: Ryzen 5 4600H laptop, GTX 1650 and
integrated Radeon (RENOIR), CachyOS and Windows 11. Benchmarks are
`scripts/perf/bench_combat.py`: 60 s of the first STG02 fight after a scripted
route; the average spreads about ±3 fps between runs, so the worst 5 seconds
and the p95 frame weigh more.

## 1. What was measured before changing code

`PORT_PROFILE` samples and sensors on Linux, no PGO, both GPUs (details in
[RELEASE_0.6.0.md](../RELEASE_0.6.0.md), step 1):

- The limit is one CPU thread, `runTaskMain`, at 93% of a core on either GPU.
  The render thread is at 45%, the integrated GPU 31% busy, and the fastest
  core holds 4.0 GHz without thermal or power throttling.
- The frame limiter does not spin below 60 fps (0.1% of the thread); no
  pipeline is created during the fight.
- Guest memory helpers are 16-17% of `runTaskMain`, chunks 021 and 015 another
  25%, the list lookup `native_004B5120` 5.4-5.9%.

Every item that could not save at least 3% of that thread was dropped for
0.6.0.

## 3. Fixes found while testing

- **Alt+Tab in exclusive fullscreen (Windows):** the window was minimized and
  the game dropped it for good. Fixed in `5724ff2`; `0f42e4d` then releases the
  swapchain while minimized, so the last frame no longer stays in front of the
  desktop. Shared code (`port/graphics/vulkan_bridge.c`): checked on Linux too
  (minimize and restore shows the game).
- **Intro music crackle (Windows):** the device queue ran dry about twice
  every 5 s; `a820adc` follows the output device. 0 dry-outs after the first
  10 s (`PORT_AUDIO_STATS`), confirmed by ear.
- **Launcher:** the GPU list leaves out software renderers; Ctrl+C or a
  signal during `--import-only` stops the running tool and removes the
  half-written folder (exit 130); **Stop** removes the unpacked RPCS3 too.
- **Window name:** the game window is **Battride War** (app_id and WM_CLASS
  `battride-recomp` on Linux).

Problems met while rebuilding Windows, none in the port's code:

- **MSYS2 now installs `sdl2-compat` (SDL2 on SDL3) as `SDL2`.** Its config
  header includes `sdkddkver.h` first, which sets `_WIN32_WINNT` to 0x0502, and
  the SDK's `cellPad.c` no longer sees `GetTickCount64`. The real SDL2 2.32.8
  (the one the November 16 package carried) was installed from the MSYS2
  archive and pinned; [WINDOWS.md](../WINDOWS.md) says how.
- **`pacman -Qi` is localized:** `build_windows_package.py` reads its English
  field names, so it runs with `LC_ALL=C` on a non-English Windows.
- **Clock 3 h ahead:** CachyOS keeps the hardware clock in UTC and Windows read
  it as local time until its NTP sync set it back. Files written before were
  dated in the future, and the launcher's first build failed with "manifest
  'build.ninja' still dirty after 100 tries". With those times reset it built.
  The zip's file times are 3 h ahead, which only affects a build started before
  about 22:10 on November 18.
